# Actors

> Roles that interact with this system. Referenced by use cases and requirements.

| Actor | Role | Description | Constraints |
|-------|------|-------------|-------------|
| LP | human | Liquidity provider whose Gnosis Safe wallet, deployed by Prophet through the Poly Safe factory, holds the USDC, is the recorded depositor and position owner, and receives every payout. The Safe's owner key (an EOA) signs every EIP-712 authorization (MintIntent, ReclaimIntent, and BurnIntent), each with a deadline, and the Operator relays it. The Safe itself calls the self-service paths (`reclaimDeposit`, `burnPosition`) through a Safe transaction the owner key signs | Can have multiple positions per vault; can only reclaim or burn on escrows and positions the Safe owns; the vault accepts an owner key only when the Safe it derives equals the named Safe |
| Operator | system | Transactional authority — escrows an LP's USDC from the LP's Safe via `depositForIntent`, credits the position via `mintPositionFor`, relays a signed reclaim or burn via `reclaimDepositFor` and `burnPositionFor`, calls `updateTick`, `mergePositions`, and `heartbeat` | Multiple addresses allowed via `mapping(address => uint256) operators`; managed by Admin via `addOperator` / `removeOperator`; gated by `onlyOperator` modifier; every Operator function also carries `touchesHeartbeat` |
| Oracle | system | Lifecycle authority — calls `createVault(marketId, tickSpacing, minimumFirstLiquidity, conditionId, yesTokenId, noTokenId)` on the factory to deploy new per-market vaults and sets initialization defaults, calls `startWindDown()` on a vault when its underlying market resolves, then `redeemOutcomeTokens()` once the ConditionalTokens contract holds the result, which turns the vault's tokens into USDC and switches every later payout to USDC at that payout | Single on-chain wallet (`address public oracle`); set by Admin via `setOracle`; should match the oracle configured on `ProphetCTFExchange` and `Resolution`; MUST be a separate account from Operator |
| Admin | human | Registry-only authority — manages who holds what role (add/remove operators, set oracle, pause trading, two-step admin transfer, add/remove/renounce admins) and sets the factory's default emergency-cancel timelock, which later vaults copy | Cannot directly call user-facing functions; registry-only; two-step transfer for admin role |
| Keeper | system | Off-chain service that monitors the CLOB and signs transactions using an Operator key to call `updateTick` and `mergePositions`. It signs the vault's orders with the same key (`signer = maker = vault`, `signatureType = POLY_1271`), and it cancels its resting orders on `EmergencyCancelExecuted`, `VaultWindDownStarted`, and `TradingPaused`, because the vault refuses their signatures at match time (decision C22) | Not an on-chain role — has no contract-level authority of its own; trust assumptions are inherited from whichever Operator key it holds |
| Factory Owner | human | Deploys the `LPVaultFactory` contract and bootstraps the role registry (initial Admin) | Sets the implementation contract address, the CTF Exchange address, the USDC address, the ConditionalTokens address, the Poly Safe factory address, the Safe proxy bytecode hash, and the initial Admin / Oracle / Operator wallets at deployment; after deployment, role management is handled by Admin, and the two Safe derivation inputs never change |
| Any Wallet | system | Any address, with or without a role, calling a vault function that has no role check | Used only for a function whose effect cannot favor its caller: `mergeCompleteSets()`, which credits the vault's measured spread to the liquidity in range before it merges the free pairs and still pays its caller nothing, and `emergencyCancelAll()` after the vault's operator-silence timelock, which freezes the vault and moves no funds. A function with no `onlyAdmin`, `onlyOperator`, or `onlyOracle` modifier is open to this actor (`initialize` checks its factory caller inline, because `factory` is not yet stored). |
